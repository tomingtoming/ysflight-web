## 第一ターゲット: 旧 YSFLIGHT の既存ファン（P0）

**まずこの層を取り込む。** 他のすべての判断はここを起点にする。

### 像

- 2000〜2010 年代に **PC（主に Windows）で YSFLIGHT を遊んでいた**層。日本発のフリーフライトシムとして
  同人・コミュニティ文化（機体 / マップ addon の自作・配布・対戦会）を共有していた。
- 多くは現役を離れている。理由は **環境の壁**（古い Windows ビルドのインストール、Mac / Chromebook /
  モバイルへの移行で動かせない）と **起動の手間**。ゲームへの愛着が消えたわけではない。
- 昔集めた / 自作した **addon 資産**（機体・塗装・マップの zip）を手元に持っていることがある。

### コアニーズ → 効く v1 機能

| 既存ファンのニーズ | それに応える v1 の事実 | 出典 |
|---|---|---|
| **あの飛行感覚そのまま**飛びたい（懐古の核） | 飛行モデル / 物理は原典 C++ を無改変 WASM 化。ハーネスのゴールデンテストで**軌道バイト同一**＝飛行挙動不変 | overview §1.1 |
| **URL を開くだけ**で動いてほしい | ブラウザ / PWA 配布。インストール・古い OS 要件なし。オフライン再起動可 | overview §1.4 |
| **昔の addon を持ち込んで**飛びたい | シングルプレイのパック取り込み（D&D / URL）→ OPFS → 遅延 materialize が**稼働中**。既存コミュニティ addon も正規化で両対応 | overview §3.2 / addon-packs §1〜§4 |
| **昔の仲間と対戦**したい | WebRTC P2P ＋ Cloudflare シグナリング。8桁ルーム / 招待リンクで対戦可 | overview §2 |

### この第一ターゲットが正当化する v1 スコープ判断

1. **「飛行挙動は不変」を最優先で死守する。** これは既存ファンの来訪理由そのもの。最適化・改変で
   ここを崩す変更は、第一ターゲットへの裏切りとして扱う。

2. **ソロのパック持ち込みは v1 で出す（稼働中で正しい）。** 既存ファンの最大の資産は「過去の addon と
   自作機体」。それをすぐ活かせることが再訪の決め手になるため、シングルプレイのパック管理は v1 の
   価値の中心に置く。

3. **マルチプレイのパック自動配信は v2 送りでよい。** v1 は原典と同じ **vanilla 契約**（全員が同じ
   パックを各自事前導入）で運用する（overview §3.4 / addon-packs §5.1）。
   - **ペルソナ的根拠**: vanilla 契約は原典 YSFLIGHT のマルチプレイ**そのままの作法**であり、既存ファンに
     とっては「いつもの段取り」で違和感が小さい。新規層には不親切だが、第一ターゲットが既存ファンである
     限り許容できる。
   - **順序の論理**: マルチ配信の要望は **ysflight-web が軌道に乗り、Web 版コミュニティで対戦会が回り
     始めてから**自然に強まる。コミュニティが育つ前に難所（DataChannel ストール＝§3.3 の `PACK_CHUNK`
     問題）を解く投資をするより、まず既存ファンを集めることを優先する。配信は需要が顕在化した v2 で
     再設計する（descope は技術都合だが、ペルソナ上も「今やる必然がない」）。

4. **NET-VERSION 非互換（原典ネイティブ版と接続不可）を受け入れる。** 既存ファンの一部は「原典の鯖と
   つなぎたい」と思うかもしれないが、v1 は **Web 版同士の新しいコミュニティ**を作る方針を取る
   （overview §2、`NET-VERSION=20260617` 固定）。原典との相互接続は非目標。

## セカンダリ: 新規のブラウザ / モバイル層（P1・土台のみ）

YSFLIGHT を知らず、カジュアルに「ブラウザで飛行機を飛ばしたい」層。**v1 では主役ではないが、土台は
用意してある**ので、第一ターゲットを獲得しながら将来に備える。

- **用意済みの土台**: タッチ操作対応（overview §1.2）、モバイル / CGNAT / 対称 NAT 向け
  **Cloudflare Realtime TURN** 中継（overview §2、multiplayer）。Mac / Chromebook / モバイルへ
  移行した**元・既存ファン**にもこの土台は効く。
- **v1 で未整備（意図的）**: チュートリアル、カジュアル導線、操作のオンボーディング。原典は操作系が
  硬派で、新規層の離脱要因になり得る。ここへの投資は第一ターゲット獲得が立ち上がってから。

## 非ターゲット（v1 で明示的に狙わない）

- **原典ネイティブ版の現役プレイヤーで「原典鯖と相互接続したい」人** — NET-VERSION で意図的に分離
  （overview §2）。Web 版は別コミュニティ。
- **大規模 mod 配信を前提にした大人数イベント運営** — マルチのパック自動配信が前提になるため v2 待ち
  （addon-packs §7・§9）。
- **デスクトップ版のフル機能（ATC 音声 / IME / マルチスレッド性能）を求める層** — Web の制約上 v1 では
  応えない（overview §1.5）。

## ペルソナ → 設計判断 早見表

| 判断 | 第一ターゲット（既存ファン）から見た意味 | v1 ステータス |
|---|---|---|
| 飛行挙動の無改変維持 | 来訪理由の核。死守 | 稼働 |
| ブラウザ / PWA 配布 | インストールの壁を撤去＝離脱組の再訪導線 | 稼働 |
| ソロのパック持ち込み | 過去 addon 資産を即活用＝再訪の決め手 | 稼働 |
| MP の vanilla 契約（配信なし） | 原典どおりの作法で違和感小。許容 | 稼働 |
| MP パック自動配信 | コミュニティが育てば要望化。**軌道に乗ってから** | **v2 送り** |
| NET-VER 非互換 | Web 版同士の新コミュニティを作る | 稼働 |
| タッチ / モバイル TURN | 移行組（Mac/Chromebook/モバイル）に効く・新規層への布石 | 稼働 |
| チュートリアル / カジュアル導線 | 新規層向け。第一ターゲット獲得が先 | 未着手（意図的） |
